# YETI — 3 règles UI OSINT-safe (à ne jamais violer)

## 1) Ne jamais “faire autorité” sur le terrain
- Pas de vocabulaire type “officiel”, “certifié”, “garanti”, “sécurisé”.
- Tout fait mutable (eau, refuges, accès, horaires) doit être présenté comme **indicatif** + daté (dernière mise à jour).
- Les limites doivent être **dans le flux** (pas cachées en bas de page).

## 2) Séparer strictement “faits” et “analyse”
- Les faits affichés doivent être sourcés (OSM, topo public, site refuge, etc.).
- Ce que l’utilisateur paie : **l’organisation + l’analyse** (diagnostic, répartition, scénarios), pas “la vérité terrain”.
- Si une section payante contient des faits, elle doit aussi contenir la source + un rappel de variabilité.

## 3) Les signaux de confiance doivent être prudents
- Pas de gros ✅ verts qui ressemblent à une validation de sécurité.
- Préférer des statuts neutres : “à vérifier”, “confirmé par X utilisateurs”, “signalé récemment”.
- En cas de doute : proposer une action (checklist / appel / lien source) plutôt qu’une affirmation.
